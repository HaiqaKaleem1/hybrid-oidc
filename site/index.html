02 Security claims & closed vulnerability windows

G1 / Theorem 1 — record-now-decrypt-later

Break either component KEM entirely and recorded hybrid traffic stays opaque: ε ≤ Advc + Advp + q·negl. Corollaries cover the “lattice paper is wrong” and “Shor breaks ECDH” scenarios.

✓ closed: future quantum decryption of stored transcripts

G2 — one-break IND-CCA (games 0–3)

Conjunction decapsulation: ⊥ if either half fails. Tampered classical half, PQ half, nonce or AAD — all rejected, with identical timing.

✓ closed: active MITM ciphertext malleation

G3 / G4 — authenticity at the weakest link

Hybrid JWT acceptance needs both signatures on the same message. Strip or graft a half and it fails. The composite never advertises more security than its weaker half.

✓ closed: half-signature forgery, algorithm confusion

Theorem 3 — channel binding

A TLS-exporter value joins the signed input, so a stolen id_token replayed on a foreign connection fails verification.

✓ closed: bearer-token replay across connections

HMK-1 — side-channel hardening (C core)

No secret-dependent branches, no secret-indexed tables, full-scan tag compare, branchless publish of the candidate key, fixed work per call, explicit zeroization — proven by measurement below.

✓ closed: timing oracles on comparison / early exit

Fixed-length encodings

Canonical length asserted before parsing everywhere — no variable-length parse differentials, and the HKDF dual-PRF side condition holds.

✓ closed: length-dependent parse & timing leaks

03 The mathematics — interactive

Number theory — the Fp combiner

Kf = N(ssc) · N(ssp) mod p, p = 2256 − 232 + 977

CIOS Montgomery multiplication, fixed 4-limb loops, branchless conditional reduction — no log/exp tables to index with secrets. Both inputs map into Fp*, so for any known half a the map b ↦ a·b is a bijection: a broken half leaves Kf uniform (bias O(1/p)).

—

Linear algebra — the F₂ mixing matrix

M = T³, T = I + S₁R¹³ + S₂R¹¹ + S₄R³¹ + S₅R⁴⁷

Click a cell to flip one input bit and watch real diffusion: cells light up wherever the 64 output bytes change. Verified: rank 512 (invertible), every output word depends on all 8 input words, single-bit flips change ≥ 17/64 bytes.

How to read this: every sealed record is ct = mk ⊕ HMAC(kek, LAB_KS‖nonce) plus tag = HMAC(kmac, LAB_TAG‖nonce‖ct‖aad), with K_f = ss_c·ss_p mod p and u = M·(ss_c‖ss_p). The receiver rejects any record whose tag does not verify — and the tag cannot be forged without K_f, which needs both KEM halves. Tampering the ct, forging the tag, guessing one or both halves, replaying, reusing keystream, truncating ct or tag, side-channel probing, or downgrading to one half — all rejected by the same construction.

06 Repository & quickstart

What's in the box

  • csrc/ — constant-time C core: CIOS Montgomery Fp, F₂ mixer, HMAC-SHA-256, wrap/unwrap, KATs, timing harness, disassembly target
  • pkg/hybridoidc/ — Alg 1–4 reference implementation + cgo bindings, 13 tests mapped to claims G1–G4
  • docs/ — formal security spec with complete proofs
  • paper/ — compiled LaTeX submission paper
  • cmd/hmktui/ — interactive TUI demo
  • tools/ — independent Python / Node cross-checkers

Run it locally

# C core: KATs + side-channel harness
cd csrc && make test && make timing

# Go suite (proofs' claims + timing regression)
go test -count=1 ./...

# Interactive TUI demo
go run ./cmd/hmktui

# Independent checkers
python3 tools/linspread_check.py
node tools/check_site_core.js

No pre-existing cipher encrypts plaintext: the keystream is derived through the HMK construction itself — field combiner → F₂ mix → HMAC extractor.
